# 2026-11-08 排障、审计与验收

## 故障与原因

用户已添加频道、扫描并重建媒体树，但 Jellyfin 网页端为空。本轮确认空库来自建库同步链路：Jellyfin 关闭了实时监控，最后扫描早于媒体文件生成；tgproxy 原来的重建操作也没有通知 Jellyfin。宿主与容器的媒体目录一致、可读，排除了挂载和文件权限问题。

当时索引为 7 个频道、693 条媒体，其中 466 个视频和 227 张图片；媒体树仍只有 83 个旧视频入口。重新生成后，旧代码又将 466 次写入覆盖成了 447 个文件。

Jellyfin 开始扫描后，进一步暴露出 tgproxy 自身的拉流尾块 bug。最后一块请求长度向下取整到 4096 倍数，剩余不足 4096 时发出零长度请求，导致 MP4 尾部索引丢失。两个实际失败视频请求尾部 1024 字节时，旧版本返回了 206 和 Content-Length，却实际返回 0 字节；ffprobe 报提前 EOF、STSZ/STCO 截断。该缺陷属于本项目实现，不能归因于 tdl。

## 已修复

| 范围 | 修复与行为 |
|---|---|
| 尾块与协议 | 尾块请求向上对齐后裁剪真实长度，不跨 1 MiB 窗口；支持普通/后缀 Range 和 HEAD；空文件非法 Range 返回 416 |
| 下载错误 | 首块失败返回 502/504，中途失败主动中断响应并记录位置，避免伪装成成功短体 |
| 缓存与取消 | 失败半块不入缓存，后续可重试；共享下载按等待者计数取消，旧取消任务不会接走新请求 |
| 并发与预取 | 需求最多 8 个、预取最多 2 个；获得名额后才分配块内存，设下载超时 |
| 句柄开销 | 128 项、1 分钟 TTL 的解析缓存与合并；独立等待者取消；失败时失效并重新解析 |
| 文件恢复 | FILE_MIGRATE 使用目标 DC，有限次重试；引用过期重新获取消息，核对文件 ID/大小，防止拼接被替换文件 |
| 历史扫描 | 使用 100 条批次，从原始消息最小 ID 推进到空页；短页、照片和服务消息不再提前结束；游标无进展时报错 |
| 视频与进度 | 过滤图片/非视频，填充 MIME；显示扫描进度；FLOOD_WAIT 按服务端时间等待并响应取消/超时 |
| 媒体归类 | 预编译且共用集号/标题规则，清理来源标签，保留 S00，兼容括号、裸数字、中文季集，避免分辨率误识别为 1x02 |
| 输出唯一性 | 同名无集号资源区分来源，同集多源保留后缀；跨季统一大小写，清洗目录碰撞加稳定标识；限制路径段长度 |
| 媒体同步 | 清单记录文件所有权/哈希/索引版本；保持根 inode；旧输出移至备份，拒绝符号链接、未知冲突和手动改动；失败尝试恢复并报告恢复错误 |
| 索引保存 | 原子保存成功后才提交内存；删除频道同时移除索引；去重同一频道 ID；消息查找使用内存索引 |
| 连接与登录 | runtime 原子发布、连接退出更新状态、旧连接取消、DC pool 关闭同步、登录就绪通知与超时、旧 session 清理、会话复制及访问缓存锁 |
| 重启恢复 | 频道 access hash 按会话隔离保存为私有文件；数字频道解析失败时查已有会话，不自动加入频道 |
| 控制台 | 扫描自动重建并通知 Jellyfin；任务互斥；失败频道保留旧索引并显示错误；单一串行轮询，不残留旧日志；同源管理请求检查 |
| 配置 | 数值/URL 校验，flag 正确覆盖文件配置，原子私有文件保存；可选 Jellyfin 通知，不带密钥跟随重定向 |

## 支持边界

- Telegram CDN redirect 未实现。CDN 涉及独立连接、AES-CTR 和内容校验，不是随机 Range 读取的简单开关；没有把它冒充成已支持。文件超过 2 GiB 本身不代表一定走 CDN。
- 文件名缺少剧名或集号时只保留稳定独立入口，不承诺自动还原真实影视信息。当前沿用一个 tvshows 库；无集号视频仍以独立分组/E00 展示。
- 大量视频首次导入时，Telegram 索引完成与 Jellyfin 媒体信息扫描完成是两个阶段。重建成功只证明入口生成，不证明所有条目已经完成探测。
- 已验证 HTTP 流、Range 和 ffprobe；未声称所有网页/手机客户端编码均可播放，也未重新执行需要人工验证码的新账号登录。服务器转码继续关闭。

## 上游契约核对

本轮使用 smart-search 抓取官方正文，并对照本地 gotd v0.163.0 与 tdl core 源码：

- [Telegram 文件下载约束](https://core.telegram.org/api/files)：precise 模式仍要求 offset/limit 对齐，单次不超过且不跨 1 MiB。
- [文件引用刷新](https://core.telegram.org/api/file-references)：过期/无效引用需重新取得来源消息，再重复调用。
- [历史偏移规则](https://core.telegram.org/api/offsets)、[getHistory](https://core.telegram.org/method/messages.getHistory)：按消息游标取更早历史，业务过滤结果不能替代原始分页状态。
- [CDN 协议](https://core.telegram.org/cdn)：独立认证、解密、校验与回源流程。
- [gotd/td](https://github.com/gotd/td)、[iyear/tdl](https://github.com/iyear/tdl)：本轮源码审计对照上游版本；当前构建改为使用文末记录的个人 fork 固定 commit，未因上游项目存在某功能便假设当前调用链已启用。
