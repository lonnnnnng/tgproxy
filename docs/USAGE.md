# 使用指南

## 登录

打开 <http://192.168.1.2:8080/>，输入国际格式手机号，发送验证码并登录；开启了两步验证时再输入密码。默认内置与 tdl 相同的公开应用标识，无需自行填写 API 凭证。登录会话保存于服务器私有配置，重启后自动恢复。

验证码过期时重新发送；重发沿用当前登录连接并更新哈希。一次待登录流程最长 10 分钟。不要把配置、会话或频道访问缓存发给他人。

## 添加频道与更新

1. 添加 `@频道名`、`https://t.me/xxx` 或数字 ID。私有频道需账号已有访问权限。
2. 点击 **扫描并更新媒体库**。
3. 等待日志显示各频道完成、媒体树生成以及 Jellyfin 通知结果。扫描会继续翻页读取历史，不再只取第一页。
4. 打开 <http://192.168.1.2:8097/>，等待 Jellyfin 的扫描结果陆续出现。

扫描期间不可添加、删除频道或同时重建。控制台显示索引中的视频数；Jellyfin 首次需要逐条读取媒体信息，因此两边数量不一定立即一致。

新内容更新时再次扫描即可；无须抢在扫描结束前手动重建。单个频道失败会保留其旧索引，并保留失败日志。

## 重建与删除

**重建媒体树**用于按现有索引重新生成入口，不会代替 Telegram 扫描。它会通知已配置的 Jellyfin 刷新。未配置通知时，可使用 Jellyfin 实时监控或手动刷新库。

删除频道后，该频道的索引会移除；再重建以同步旧文件。仅本项目清单拥有的文件会被更新或移至 `media.backups/`，其他文件和手动改动不会被直接覆盖。

同剧跨频道按季集归类；同一集不同来源保留来源后缀；同名无集号视频使用来源标识区分，避免预告或电影互相覆盖。文件名不足以提供真实剧名时保留独立入口，命名规则不能代替人工判断。

## 播放

Jellyfin 地址为 <http://192.168.1.2:8097/>，手机也使用此服务器地址及已有账号。管理员密码不记录在仓库。

服务器音视频转码保持关闭；网页和手机能否直接解码取决于客户端支持的编码。拖动后首次读取新分块需要等待 Telegram，重复位置可复用缓存。

## 排查

| 现象 | 检查方式 |
|---|---|
| 控制台有视频，Jellyfin 暂时没有 | 等扫描和自动重建完成，确认通知结果，再看 Jellyfin 媒体库扫描任务 |
| 扫描失败 | 查看控制台最后错误；失败频道会保留旧索引。限流会按服务端等待时间重试 |
| 视频一直探测失败或无法拖动 | 查看 tgproxy 与 Jellyfin 日志；尾块截断已于 2026-11-08 修复，可见审计记录 |
| 502/504 | 源请求失败或超时，重试会重新取数据；失败数据不会永久留在缓存 |
| 文件引用已替换 | 重新扫描并打开，代理不会拼接不同文件的数据 |
| CDN redirect unsupported | 当前还不支持 Telegram CDN 重定向，需要独立协议适配；并非所有超过 2 GiB 的视频都不支持 |
| 外网访问 | 当前流地址使用局域网 IP；切换外网地址需同时确保 Jellyfin 容器和客户端可达 |

运维配置和日志命令见 [DEPLOY.md](DEPLOY.md)。
